# sample-07：カフェ・喫茶店サイトの WordPress テーマ（ひととき珈琲）

[sample-04](../sample-04/)（静的サイト）を、WordPress のクラシックテーマにしたものです。見た目はそのままに、お店の方が管理画面から更新できるようにしました。

デモ: https://chameleon05119.github.io/portfolio/sample-07/ （ボタンを押すと WordPress Playground が起動し、サイトと管理画面を触れます）

## 管理画面から更新できるもの
| 管理画面 | 内容 | 反映される場所 |
|---|---|---|
| 投稿 | お知らせ（カテゴリ: メニュー／営業／お店） | トップの「お知らせ」と最初の画面の最新 1 件、お知らせ一覧・カテゴリ別一覧・記事 |
| メニュー | 品目（価格・「〜」「＋」の書き方・ひとこと・ICE可／持ち帰り可・トップに表示）と分類（英字の見出し・注意書き・写真・並び順） | メニューページ、トップの「メニュー」 |
| お店の情報 | 営業時間・ラストオーダー・定休日（毎週／第◯曜日）・臨時休業／臨時営業・住所・電話・Instagram | 「本日の営業」、営業カレンダー、アクセス欄、スマホメニュー、フッター、トップの説明文 |
| 外観 > メニュー | ヘッダー・フッターのナビ（項目の「説明」に英字を入れるとスマホメニューに出る） | ヘッダー・スマホメニュー・フッター |

トップの紹介文・写真（お店のこと・過ごし方・店内）は頻繁に変わらないため、テンプレートに直接書いています。

## 作りのポイント
- **プラグインなし**: メニューはカスタム投稿タイプとタクソノミー、価格などは独自の入力欄、お店の情報は設定ページ（Settings API）で作り、ACF などに依存しない
- **お店の方が迷わない管理画面**: 品目の編集画面は本文欄なし（品名・価格・ひとことだけ）、定休日は曜日のチェックと「第◯◯曜」の選択、臨時休業は「2026-12-30〜2027-01-03」のように期間でも書ける。お店の情報は管理者でなくても（編集者の権限で）更新できる
- **設定を 1 か所に**: 定休日の表記（「水曜・第3木曜」）は設定から組み立てるので、曜日を変えればトップ・スマホメニュー・フッター・説明文がまとめて変わる。「本日の営業」とカレンダーの判定にも同じ設定を JS に渡して使う
- **編集画面も公開ページと同じ見た目**: 投稿の編集画面に、公開ページと同じ書体・色・本文の書式を当てる（editor-style）。文字色はサイトの色だけから選べるようにして、見た目が崩れないようにしている
- **お知らせの絞り込みはカテゴリ別の一覧ページ**: 静的版の JS の絞り込みを、URL のあるカテゴリ別一覧（/news/category/menu/ など）に置き換え。ページ送り付き
- **SEO**: タイトル、説明文（ページごと）、OGP をテーマで出力。SEO プラグインを入れたときは二重にならないよう出さない
- **表示速度**: 使わないブロック用 CSS・絵文字のスクリプトを外し、フォントは描画を止めずに読み込む。JS は defer

## 実際のサイトに入れるとき
- 必要な環境: WordPress 6.5 以上、PHP 8.0 以上
- `npm run build` で作った `dist/hitotoki.zip` を「外観 > テーマ > 新規追加 > テーマのアップロード」から入れて有効化する（有効化のときに /menu/ の URL も作られる）
- 「設定 > 表示設定」でホームページを固定ページ（トップ）、投稿ページを「お知らせ」（スラッグ `news`）にする。「設定 > パーマリンク」は `/news/%post_id%/` を推奨
- 「お店の情報」は**編集者**の権限でも更新できる（お店のスタッフに管理者権限を渡さずに済むように）
- 公開するときは「設定 > 表示設定」の「検索エンジンでの表示」のチェックを外す（デモは検索エンジンに載せない設定）
- フッターの「架空のお店のデモサイトです」の 1 行（`footer.php`）とトップの文章・写真（`front-page.php`）は、お店に合わせて書き換える
- 外部への通信は Google Fonts（見出しの明朝体と英字）のみ
- メニューの品目は 1 ページに全件出す（数十品目を想定）。分類を付け忘れた品目は最後の「その他」に出て、管理画面の一覧に注意が出る
- 日本語専用のテーマのため、文言は翻訳関数を通さずに書いている
- テーマの zip に SCSS は含まれない（CSS は圧縮せずに出しているので、そのまま手直しできる）。SCSS で直すときはこのリポジトリの `src/scss/` を使う

## ファイル構成
| パス | 内容 |
|---|---|
| `theme/hitotoki/` | テーマ本体（これを `wp-content/themes/` に置く、または zip にしてアップロード） |
| `theme/hitotoki/inc/` | 機能ごとの PHP（設定・読み込み・お店の情報・メニュー・表示用の関数・SEO） |
| `src/scss/` | テーマの SCSS（sample-04 と同じ FLOCSS 構成＋ `project/_wp.scss`・`component/_content.scss`・`editor-style.scss`） |
| `seed/` | デモの初期データ（お知らせ・メニュー・ナビ）と写真。Playground の起動時に流す |
| `scripts/` | ビルド（`build.mjs`）、開発サーバー（`dev.mjs`）、Playground の起動手順（`blueprint.mjs`） |
| `src/landing/` | 作品集から開く入口ページ |

## 開発
```bash
npm ci
npm run dev        # http://127.0.0.1:9400/ （管理画面 /wp-admin/ はログイン済み）。Docker・PHP は不要
npm run build      # CSS をビルドし、dist/ にテーマの zip・初期データ・blueprint・入口ページを作る
npm run lint:php   # PHP の構文チェック（PHP 8.0。PHP を入れていなくても動く）
```

- 開発サーバーは WordPress Playground（ブラウザでも動く WordPress）を Node で動かす。初回だけ WordPress（日本語版）を `.playground/` にダウンロードする
- テーマのフォルダをそのまま読み込むので、PHP・JS は保存して再読み込みすれば反映される。SCSS は保存のたびに自動でビルドされる
- データは起動のたびに初期データから作り直す（管理画面での変更は残らない）
- `LOGIN=0 npm run dev` で未ログインの表示、`PORT=9402` で別のポート
- `.playground/wordpress.zip` は初回に取った版のまま使う。WordPress を新しくして確かめるときは消してから起動する
- 公開デモ（Playground）は WordPress の最新版で起動する。WordPress の大きな更新のあとは、デモが動くか確かめる
- 初期データのお知らせは 2026 年 8〜10 月の日付。臨時休業の初期値（年末年始）も 2026 年のもの
