# sample-09：広告用 LP ＋ 広告バナー ＋ 計測（オンライン簿記講座・ボキコツ）

忙しい社会人向けの、架空のオンライン簿記講座「ボキコツ」の広告用ランディングページです。広告から来た人に無料体験を申し込んでもらうための縦長の LP と、そこへ人を呼ぶ広告バナー（2 案 × 4 サイズ）、申し込みまでを測る計測（Google タグ マネージャー向けの dataLayer）を、構成・デザインからコーディングまで作りました。

## ページ
LP（トップ）／申し込みの完了／特定商取引法に基づく表記／個人情報の取り扱い／広告バナーの一覧（ポートフォリオ用）

## 作りのポイント
- **広告 LP の構成**: キャンペーンの帯 → 最初の画面（コピー・申し込みボタン・数字）→ お悩み → 3 つの特長 → 1 日の使い方 → カリキュラム → 学習プランの目安 → 受講生の声 → 講師 → 受講料 → ほかの学び方との比較 → よくある質問 → 申し込みフォーム
- **申し込みボタンだけオレンジ**: ブランドの緑と分け、押せるボタンに見えるよう下に厚みを付けた。スマホでは最初の画面を過ぎると画面下に追従ボタンが出て、フォームが見えたら隠れる
- **キャンペーンの締切**: `data-deadline` に日時を書くと、帯・受講料・フォーム横の締切の日付と「あと ◯ 日」が入る。締切を過ぎたら、キャンペーンの表示を消して通常価格に自動で戻す（終わったキャンペーンが出たままにならない）。デモでは締切を「今月末」にしている
- **学習プランの目安**: 目指す級・1 日の時間・週の日数から、カリキュラムを 1 周できる週数と時期を出す。読み上げはスライダーを止めてから 1 回だけ
- **画像を使わない画面イメージ**: 最初の画面のスマホ（講義動画・問題）と、特長の中のアプリの画面は HTML/CSS で組んでいる。講師は架空の人物なのでイラストにした
- **申し込みフォーム**: 入力し終えた項目からその場で確認し、送信時は最初のエラーの項目へ移動。受講料のボタンから来たときは、選んだコースがフォームで選ばれた状態になる。JS が動かない環境では送信ボタンを押せないようにして案内を出す
- **動き**: 最初の画面の問題に答えが入る・リングが 1 周する・札が浮かぶ、スクロールでの表示、FAQ のなめらかな開閉。OS の「視差効果を減らす」設定ではすべて止める

## 広告バナー
`banners/banners.html` に HTML/CSS で組み、`npm run banners` で指定のサイズちょうど（等倍）の PNG に書き出す（出力は `src/public/banners/`）。文言・価格を変えたら全サイズを一度に作り直せる。

| 案 | 訴求 | サイズ |
|---|---|---|
| A | 時間「1日15分、スマホで。働きながら簿記2級。」 | 1080×1080 / 1200×628 / 300×250 / 320×100 |
| B | 価格「期間限定 受講料 20%OFF」 | 同じ 4 サイズ |

A/B のどちらが申し込みにつながったかを比べられるよう、広告のリンク先には案とサイズごとに違う `utm_content`（例: `a-1080x1080`）を付ける想定。一覧ページ（`banners.html`）のバナーは、その UTM と計測の確認モードを付けた LP にリンクしている。

## 計測
`main.js` が「何が起きたか」を決まった名前で `window.dataLayer` に送る。GA4 へどう送るか（どれをコンバージョンにするか等）は Google タグ マネージャー側で決める。GTM のタグは `_partials/head.html` にコメントで置いてあり、本番ではコンテナ ID を入れて有効にする。

| イベント | いつ | パラメータ |
|---|---|---|
| `cta_click` | 申し込みボタンを押した | `cta_position`（header / fv / plan / price / fixed）、`cta_text` |
| `plan_select` | 受講料のボタンでコースを選んだ | `course_level`（3 / 2 / 3-2） |
| `section_view` | セクションが画面の真ん中を通った（各 1 回） | `section_id`（fv / worry / feature / … / trial） |
| `faq_open` | よくある質問を開いた | `faq_question` |
| `plan_simulate` | 学習プランを操作し終えた（止めて 1.2 秒後に 1 回） | `course_level`、`minutes_per_day`、`days_per_week`、`weeks` |
| `form_start` | フォームに入力を始めた（1 回） | `form_id` |
| `form_error` | 送信したがエラーがあった | `form_id`、`error_fields`（例: `email,agree`） |
| `form_submit` | エラーなく送信した | `form_id`、`course_level` |
| `generate_lead` | 完了ページを開いた（フォームから来たときだけ 1 回） | `form_id`、`course_level`、`utm_source` などの UTM |

- **コンバージョンは完了ページで 1 回だけ**: 送信時に印を残し、完了ページで送ったらすぐ消す。再読み込み・ブックマーク・直接アクセスでは数えない
- **UTM をセッションの間だけ覚える**: 広告から来たときの `utm_*` を sessionStorage に入れ、`generate_lead` にいっしょに送る（LP の中でページを移っても、どの広告から来た申し込みかが分かる）
- **個人情報を送らない**: 名前・メールアドレスは dataLayer にも sessionStorage にも入れない（`form_error` も項目名だけ）
- **計測の確認モード**: URL に `?debug=1` を付けると、送ったイベントを画面の左下に出す（GTM のプレビューを使わなくても確かめられる）。同じタブの間は完了ページでも続き、「終了」か `?debug=0` で終わる
- GTM で作るもの（例）: 変数＝データレイヤー変数 `cta_position` などイベントのパラメータ、トリガー＝カスタムイベント（イベント名）、タグ＝GA4 イベント（イベント名をそのまま渡す）。GA4 では `generate_lead` をキーイベント（コンバージョン）にする

## 開発
```bash
npm ci
npm run dev
npm run build      # dist/ に出力
npm run banners    # 広告バナーを PNG に書き出す（og.png も更新）
```

動作の確認（全ページ・全幅のチェック＋この作品固有の操作・計測のイベント）:
```bash
npx vite preview --port 5189 &
node ../../pj-chameleon/30_engineering/tools/site-check/check.mjs http://localhost:5189/index.html http://localhost:5189/thanks.html http://localhost:5189/banners.html --flows ./scripts/check-flows.mjs
```
